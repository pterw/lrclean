# Phase B2 Offload Implementation Plan (stage, undo, purge)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Take the files of the reject check's approved removal list off their place in the photo folders in two
owner commands: `stage` renames each file and its sidecars into the tool's staging folder (undoable), `purge`
deletes the staged files (the only step that frees space). Every file is hashed again against both archive copies
before either step. Nothing is built or run until this plan is reviewed, read from outside, and the owner says so
(RC-57).

**Architecture:** Small modules `lrdup/mover_*.py` (the design's `mover.py`, split by what each decides), one new
test file per module, one shared test helper, one `cli.py` task, and one task that makes the reject check's hold of
a shared sidecar symmetric (AH, rule 29). Tasks of one wave touch disjoint files.

**Tech Stack:** Python 3.13 standard library (`hashlib`, `json`, `os`, `threading`, `unittest`); Windows paths.

**Spec:** `docs/superpowers/specs/2026-11-11-lr-cleanup-design.md`, "Phase B2: offload (gated)" at commit ad01b3a
(rules 32 to 45, Verification, Known limits, Not in this phase) and the reject check's rules 24 to 31 (what the
list holds; rule 29 as AH changes it). Rulings: workspace `context.md`, RC-57 to RC-61 and RC-64 to RC-70;
`CLAUDE.md` H1 to H8, R1, R4, R10, R11, R14, R16 to R18, R22.

Sections: Global Constraints=brief, Review Focus=reference, Dispatch=reference, Tasks=brief, Spec coverage=reference, Controller steps=reference, Not in this plan=reference

## Global Constraints

- B2 changes no existing module but `lrdup/cli.py` (task AE) and `lrdup/rejects.py` (task AH). It reuses
  `backup.ticked`, `hashing.full_hash`, `reject_archive.load_evidence` and `archive_state`, `backup_plan.is_inside`,
  `catalogs.is_stale`, `store.latest_scans` and the `cli` helpers `_stale_catalogs`, `_rejects_coverage` and
  `_require_archive_roots` as they are. No catalog is opened for writing (H2); no write to an archive root, a backup
  root or the unreliable drive (R11); nothing is written outside `work/staging/`, `work/journal/`, `out/` and the
  folders of a path under `photo_root` that a rename leaves or returns to (rule 38).
- Python 3.13, standard library only, `unittest`, LF files; tests run as `python -m unittest discover -s tests`.
  PRIVATE DATA: fixtures plainly synthetic (`shoot-a`, `IMG_0001.ARW`); no real path or name anywhere; the tool
  never runs on a real folder.
- Test safety (RC-61): every test that touches a path builds its tree in `tempfile.TemporaryDirectory()` through
  `tests/mover_world.py`, which hands the mover seams that raise `Outside` before the call when a path lies outside
  that tree, and a `stat` that gives each archive root its own `st_dev` and the source another (the tree lies on
  one volume). A test or planted defect that would touch another path fails first. Exceptions, each stated: V reads
  bytes only and touches no path; W's tests of the real `append` and `write` use their own temporary directory.
- Fail closed: any doubt (an unreadable `stat`, a name matching two entries, a missing sidecar, a differing hash, an
  invalid journal line) holds the row or stops the command; nothing is guessed.
- Every decision is one expression on one line, so a planted defect can replace it. One test per behaviour, named
  by its rule number; a comparison of several fields gets a case per field (L10); a walk over a sequence gets
  cases for the first, the previous and a skipped item (L14); a name check compares what Windows opens (L15).
- Code tasks never commit; the controller lands each patch with the task's subject, no trailer. No pre-commit
  configuration exists.
- Size: AA, AC and AE may exceed five minutes. An implementer who finds that says so in its report; a split pushes
  command bodies into a `mover_*` module and leaves `cli.py` as wiring (the controller decides, RC-67).

## Review Focus

- A file leaves its folder only when its hash, both archive copies' hashes (and a `twin`'s) are equal in this run,
  the destinations are on volumes of their own, and the row's whole family passes first (rules 35, 36).
- The journal line is on disk before its step, in `stage`, `undo` and `purge` alike; a torn last line is repaired
  with a marker and read as before; any other invalid line is exit 2; an unplaceable `begin` holds only its row
  (rule 39).
- `undo` never overwrites, never creates a folder under a library root, never writes through a link, and leaves a
  partly purged family staged. `purge` holds a family with fewer files than the journal's `family` count.
- `purge` deletes only the set whose SHA-256 the owner approved, sidecars before the reject, permanently.
- A dry run writes nothing and reads no content (rule 42); the same-file and volume tests hold at `stage` and again
  at `purge`. After a stall nothing is written and nothing moves (rule 43).
- The two approvals (the list's and the purge set's) are each decided by one function in `mover_gate`.

*List (V), `lrdup/mover_list.py`.* `ListRow(NamedTuple)`: `source: str, bytes: int, mtime_ns: int,
sidecars: tuple[str, ...], sidecar_bytes: int, dests: tuple[str, ...], twin: str`. `ListError(ValueError)`.
`LIST_NAME = "reject-removal-list.csv"`. `check_list_path(list_path, base)` raises `ListError` unless
`os.path.abspath(list_path)` and `base/out/<LIST_NAME>` are equal through `paths.norm` (rules 3, 32; any other
spelling, a copy or a short-name alias is refused); AE calls it before a byte is read. `list_sha256(data: bytes) ->
str` (lowercase hex). `approved_sha(text) -> str` (64 hex digits, any case, returned lowercase, else `ListError`).
`read_list(data: bytes, roots: int) -> list[ListRow]` parses the same buffer (`utf-8-sig`, CRLF rows); the header is
exactly the reject check's, `source, bytes, mtime_ns, sidecars, sidecar_bytes, dest_1..dest_<roots>, twin`, with
`roots >= 2`; it refuses (rule 32) another header, an unreadable row, a negative size, a path twice as a `source`
or as the `source` of one row and a sidecar of another (by `paths.norm`), and a name ending in a dot or space or
holding a colon. A sidecar listed by two rows is not refused. `shared_sidecars(rows) -> dict[int, str]` maps the
index of each row that shares a sidecar path (by `paths.norm`) with another row to that path as listed.
`select(rows, only: Sequence[str]) -> list[ListRow]` keeps list order, compares with `paths.norm`, `ListError`
for a name that is no row; no `only` keeps all.

rename, remove, rmdir, makedirs, listdir, append, write, clock, abort, now`. `is_link(path) -> bool` is a symbolic
link or a junction. `append(path, data: bytes)` appends and fsyncs; `write(path, data: bytes)` writes a temporary
file then `os.replace`s it (the journal and `out/` go through these two, so a test can refuse them). `REAL` holds
`os.stat`, `None`, `lambda p: os.path.islink(p) or os.path.isjunction(p)`, `hashing.open_binary`, `os.rename`,
`os.remove`, `os.rmdir`, `os.makedirs`, `os.listdir`, the two writers, `time.monotonic`, `os._exit`,
`store.utc_now`. `Folders(NamedTuple)`: `base, photo_root`. `allowed(folders, path, kind) -> bool`, `kind` in
`journal` (`base/work/journal`), `out` (`base/out`), `staging` (`base/work/staging`), `source` (under `photo_root`;
a `paths.norm` prefix at a `/`); `check_write(folders, path, kind)` raises `WriteRefused(ValueError)`.
`Stopped(RuntimeError)`. `Ctx(NamedTuple)`: `seams, folders, base, batch, stop` (`stop` a `threading.Event`);
`new_ctx(seams, folders, base, batch) -> Ctx` makes the event. `guard(ctx, path, kind)` is `check_write` and then
raises `Stopped` when `ctx.stop` is set; every write, rename and remove of a mover module calls `guard` before its
seam (the journal's `stalled` line calls `check_write` only). `watch(work, *, ctx, stall_seconds, journal_write,
poll=0.05) -> tuple[object, bool]` runs `work(tick)` on a daemon thread as `backup.run_manifest` does; `tick` raises
`Stopped` once `ctx.stop` is set; with no `tick` for `stall_seconds` it sets `ctx.stop`, then calls
`journal_write("stalled", seconds=...)`, then `ctx.seams.abort(5)`, and returns `(None, True)`; an exception of
`work` is re-raised.

*Journal (X), `lrdup/mover_journal.py`.* `work/journal/mover-<batch>.jsonl`, one JSON object per line with `event`
and `at` (the marker has no `at`). Events, a closed set: `start` (`op`, `batch`, plus for `stage` `list_sha256`,
`approved_sha256`, `scans` as `[kind, id]` pairs, for `purge` `purge_sha256`; `purge` and `undo` append their own
`start`), `begin` and `end` (`op` is `stage`, `purge` or `restore`; `row` the list index, `kind` `reject` or
`sidecar`, `original`, `staged`; the first `begin` of a row at `stage` also `family`, the number of files of the row
that will be renamed; `begin` also `bytes`, `mtime_ns`, `file_index`, `sha256`, `dests` as `[dest, sha256]` pairs,
`twin`, `twin_sha256`; `end` also `state` `staged`, `purged` or `restored`, and the staged file's `bytes`,
`mtime_ns`, `file_index`), `held` (`op`, `row`, `source`, `kind`, `reason`, `file`), `stalled`, `repaired` (the
marker `{"event": "repaired"}`). `JournalError(ValueError)`. `Journal(path, ctx).write(event, **fields)`: `guard`,
then one `seams.append` of one line, so the line is on disk before its step. Before its first append a `Journal`
reads the file through the opener; when the last line has no newline it appends a newline and the marker line, then
its own line. `Journal.run_step(begin: dict, do, end) -> object` writes the `begin` line, calls `do()`, then writes
the `end` line with the fields `end(result)` returns, and returns the result: the one place where `stage`, `undo`
and `purge` take a step, the `begin` written in the same expression that calls `do`. `read_journal(path, ctx) ->
list[dict]`: a last line without a newline and the line just before a marker are ignored whatever they hold; any
other line that is not a JSON object with a known `event` raises `JournalError`. `Entry(NamedTuple)`: `row, kind,
original, staged, bytes, mtime_ns, file_index, sha256, dests, twin, twin_sha256, family, state`, `state` in
`staged`, `restored`, `purged`, `open_stage`, `open_purge`, `open_restore` (a `begin` with no `end`); `family` is
the row's first-`begin` count on every entry of the row; `entries(lines) -> list[Entry]`, one per file in journal
order, its latest op. `place(entry, ctx) -> str` is `done`, `not_done` or `unplaced`, by looking (rule 40): a stage
`begin` is `not_done` when the original exists and the staged does not, `done` when the reverse, else `unplaced`; a
purge `begin` is `done` when the staged file is gone, `not_done` when present; a restore `begin` is `done` when
the file is at the original path, `not_done` at the staged path, else `unplaced`. `write_results(path, op, lines,
ctx)` writes `out/stage-<batch>.csv` or `out/purge-<batch>.csv` from the journal's lines: one row per
`entries(lines)` entry of that `op` and one per `held` line of that `op`; columns `source, kind, staged, bytes,
sha256, state, reason` (`state` `staged`, `purged`, `held`).

### Task U: the synthetic world for B2 tests (RC-61)

`Wave:` 1 · `Touches:` tests/mover_world.py, tests/test_mover_world.py · `After:` none · `Mode:` code

**Behaviour:** `World(tmp)` builds `base/` (with `work/config.json`), a photo root and two archive roots in `tmp`.
`add(rel, data, mtime_ns)` writes a file under the photo root; `archive(path)` copies it to both roots and writes
the manifests and verified lists of B1 into `out/` (`backup_plan.write_manifest`, `backup_verify.write_verified`);
`removal_list(rows)` writes `out/reject-removal-list.csv` in the reject check's format (`utf-8-sig`, CRLF) and
returns `(path, sha256)`. `ctx()` gives a `Ctx` whose seams raise `Outside` (an `AssertionError`) before the call
for a path outside `tmp`; the fake `abort`, `clock`, `now`, `attrs_of` and `is_link` (false unless `links` names the
path) are its own. Its `stat` gives a path under each archive root that root's own `st_dev`, another than the photo
root's, and `ids[path] = (dev, ino)` overrides one path's pair (a hard link into an archive root is otherwise
hidden). `main(*argv) -> (code, out, err)` runs `cli.main` with those seams, always with `--base` inside `tmp`
(anything else fails the test), and with `volume_of` (from the same fake `st_dev`) and `free_bytes` fakes, so that
`cli._require_archive_roots` accepts two roots in one tree; `store.connect` and `read_manifest` are existing and
unwrapped and run on that base only. `listing()` maps each path under the photo root to (size, mtime_ns). Until W
has landed the `Seams` and `Ctx` are literal copies; W replaces them by the import.

**Interfaces:** produces `World`, `Outside`; consumes `backup_plan`, `backup_verify`, `reject_out`'s header.

**Acceptance:**
1. A path outside `tmp` raises `Outside` for each seam (`stat`, `rename`, `remove`, `rmdir`, `makedirs`,
   `listdir`, `append`, `write`, the opener).
2. The two archive roots and the photo root report three different `st_dev`; `ids` overrides one field alone.
3. After `archive(path)`, `reject_archive.archive_state` reports `ok` for that source; `removal_list` returns the
   SHA-256 of the bytes it wrote.
4. `World.main` hands `cli.main` a `volume_of` and a `free_bytes`: a call of `cli._require_archive_roots` with the
   World's run values accepts the two roots, and `main` with a `--base` outside `tmp` fails.

### Task V: the approved list (rule 32)

`Wave:` 1 · `Touches:` lrdup/mover_list.py, tests/test_mover_list.py · `After:` none · `Mode:` code

   is added when AF lands (before it `tests/mutants/mover.json` does not exist and the gate would fail on every
   landing); give every implementer `context.md`
   and the answers to this plan's questions; commit the plan after its re-review and after the outside read of this
   plan has been settled (RC-57). Nothing of B2 is built until the owner says so.
2. After each landing: the change note, then `gate-runner` at that HEAD in a clean detached worktree (L5).
   `mutants-mover` must report 6 after AF (the entry is added just before the gate-runner of AF's landing). AH is
   landed alone, after the second backup's verify has ended and with no other landing, gated by `unit` and
   `mutants-rejects`.
3. After AG: a reviewer runs `stage`, `undo` and `purge` end to end on a synthetic tree through `World` (never a
   real drive) and reads the journal and both result files (L12, L13).
4. The outside read by the owner's chosen reader (RC-57) of the built code, before any real run.
5. Hands-on pilot, the owner's word for each step, Lightroom closed, both archive drives identified by label and
   serial: `catalogs` and `rejects` run after AH has landed, giving the list and the SHA-256 the owner approves; ten
   rows picked with `--only` (one with a sidecar, one with a `twin` if the list has one), a dry run read by the
   owner, `stage --apply`, a listing against the one before, the owner's check in Lightroom, `undo --apply`, the
   listing equal. Opening Lightroom changes a catalog: `catalogs` and `rejects` run again, giving a new list, a new
   SHA-256 and a new approval; then `stage` of the same ten and, only when the owner says so, `purge`.
6. The real batch only after the owner has seen the pilot, with the same rule after any opening of Lightroom. Before
   it: Lightroom closed, both archive drives connected, and the SHA-256 of the list to stage the one the owner
   approved. The controller runs it (L19), the owner told first, in the background with `EXIT <code>` logged; the
   removal from the catalogs follows in Lightroom (R16, R17).

- Any write to an archive drive, a backup root or the unreliable drive; a restore of a purged file from an
  archive; a Recycle Bin purge; deleting a catalog file or a folder under a library root.
